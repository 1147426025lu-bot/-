========================================================================
支撑材料使用说明（README）
========================================================================

一、这份附件包是什么

  本包是论文《山区洪涝灾害下无人机运输与通信协同优化》的支撑材料，
  含完整可运行源程序、结果提交表、结果数据与插图、论文源文件，以及
  《AI 工具使用详情》。论文正文另行单独提交。

  完整的复现序列、输入数据的哈希口径，以及一份如实列出的「尚未进行
  的复核」清单，见 results/_交付与复现说明.txt。需要复现或核对时请先
  读那一份；本文件只交代目录怎么摆、第一步怎么起。

二、目录结构（解压后请保持原样）

    main.tex                   论文入口（XeLaTeX 编译）
    sections/                  论文各章 .tex 源文件
    code/                      全部 Python 源代码
    results/                   结果数据（.csv / .json）与《交付与复现说明》
    figures/                   论文插图（含 .drawio 可编辑源文件）
    数据/                      ← 位置是硬性的，见第三节
    结果提交表-已填写.xlsx     按赛题模板回填的提交表
    结果提交模板.xlsx          赛题下发的空模板（回填脚本的输入）
    AI工具使用详情.pdf /.tex   AI 工具使用情况说明
    build_submission.py        打包脚本（重建本压缩包）

  请勿移动、重命名或删除其中任何文件。

三、「数据/」必须留在工程根目录，且与赛题原件逐字节一致

  程序运行所需原始基础数据均来自赛题提供的文件（附件一的基础数据、
  附件二的地理空间数据），本队未作任何修改。

  代码默认按本文件所示的目录读取原始数据：公共数据加载模块
  （code/core.py）以工程根目录下的 数据/ 为数据根，各求解脚本据此
  加载。因此有两条硬约束：

    · 数据/ 必须留在解压后的工程根目录，不能挪进 code/ 或其他子目录；
    · 不能缺其中任何一份——缺了，方案加载器会判定「输入数据与方案
      记录不一致」并拒绝读入，脚本一步也走不下去。

  第二条正是本包随包收录赛题原始数据的原因。赛题原始数据按惯例可
  不由支撑材料重复分发，但方案记录中存有这些文件的逐字节哈希（共 17
  份），缺一即全链拒绝加载，故此处不作选择性打包。

四、运行（完整序列见 results/_交付与复现说明.txt）

  0) 环境：Python 3（论文实测 3.14.0），依赖 numpy / scipy / pandas /
     matplotlib / seaborn / networkx / openpyxl，实测版本号见表 A.1。
     中文 Windows 控制台须先设环境变量 PYTHONIOENCODING=utf-8，否则
     脚本的中文输出与文件名会报编码错。
  1) 求解：依次运行 code/q1.py、q2.py（--engine v2）、q2_exact.py、
     q3.py、q4.py。
  2) 独立复核：code/verify.py（应 12 项全过）、code/tests_regression.py
     （应 33 项全过、0 跳过）。
  3) 数字与图表：先跑五个只读派生脚本，再跑 paper_metrics.py、
     fill_results.py、figures.py 等。
  4) 编译与打包：latexmk -g -xelatex main.tex，再 build_submission.py。

  注意：任一落盘记录被改动、或其源码哈希失效时，加载器会报错而不会
  静默沿用过期方案。遇到这类报错，请从第 1 步起重跑整链。

五、体积说明

  压缩包体积主要来自赛题原始数据：共 17 份，压缩后约 17.0 MB，占全包
  约六成；其中两份 30 m DEM 文件（.tif 与 .mat）合计约 13.3 MB。原因
  见第三节。
